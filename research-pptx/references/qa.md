# 검수

첫 렌더링에는 대개 문제가 몇 개 있다. 찾아서 고치고, 고친 슬라이드만 다시 렌더링한다. 연구 문서의
검수는 "보기에 괜찮은가"에 더해 "논리가 이어지는가", "근거가 맞는가"를 본다.

## 1. 렌더링 확인

```
powershell -ExecutionPolicy Bypass -File <skill>/scripts/ppt_export.ps1 "<deck.pptx>" "<out_dir>" [-Slides "9,12,13"]     Windows + PowerPoint
soffice --headless --convert-to pdf "<deck.pptx>"                                           그 밖의 환경
```
그림을 직접 열어 본다. `ppt_export.ps1`이 오류 없이 끝나면 PowerPoint가 파일을 정상으로 연 것이다.
LibreOffice는 글꼴을 대체해 글자 폭이 달라질 수 있으니, 아슬아슬하게 들어간 글은 넘친다고 보고
사용자에게 확인을 부탁한다.

**모아서 먼저 본다.** 그림을 한 장씩 여는 것은 검수에서 가장 비용이 큰 일이다.
```
python -I <skill>/scripts/contact_sheet.py "<out_dir>" "<out_dir>/sheets"            아홉 장씩 한 그림
python -I <skill>/scripts/contact_sheet.py "<out_dir>" "<out_dir>/sheets" --cols 2 --rows 2    글이 빽빽한 덱
```
모아 보기로 넘침, 겹침, 빈 자리, 장끼리의 어긋남을 훑고, 이상해 보이는 장과 표·작은 글씨가 많은 장만
한 장씩 크게 연다. 고친 뒤에는 고친 장만 `-Slides`로 다시 렌더링해 확인한다. 본 장은
`progress.py set work/progress.json <번호> 검수함`으로 기록한다. 모아 보기로만 본 장도 문제가 없으면
`검수함`으로 적되, 글자가 읽히지 않을 만큼 작게 보였던 장은 크게 열어 본 뒤에 적는다.

슬라이드마다 볼 것:
- **글자 넘침·잘림**(가장 흔하다)
- 도형·그림·글의 겹침, 캡션이나 출처가 본문과 부딪침
- 그림이 찌그러지거나 흐림, 그래프 글자가 읽히지 않을 만큼 작음
- 템플릿·지난 문서의 문구나 그림이 남아 있음, 빈 자리 표시자
- 단어나 숫자·단위가 줄 중간에서 갈라짐

슬라이드끼리 비교해서 볼 것:
- 같은 유형의 슬라이드에서 제목·그림·캡션의 위치와 크기가 같은가
- 글꼴·색·글머리 기호가 프로필과 같은가
- 그래프끼리 색, 글자 크기, 축 표기 방식이 같은가

## 2. 내용 점검 스크립트

```
python -I <skill>/scripts/deck_check.py "<deck.pptx>" [--max-chars 450] [--min-pt 10] [--text]
```
읽기 전용이다. 슬라이드별 글자 수와 그림·표·차트 수를 보여 주고 아래를 찾는다.
- 남은 `[확인 필요]`, `[출처 필요]`, 양식의 안내 문구
- 빈 자리 표시자, 제목 없는 슬라이드
- 글이 많은 장(`--max-chars`: 발표용은 200~300. 표가 많은 연차 보고·회의 자료는 한 장에 1,000자를
  넘기도 하므로 지난 문서의 수준에 맞춰 올린다)
- 작은 글자(`--min-pt`: 작성 요령의 하한으로)
- 그림·표 번호의 빠짐·중복·순서
- 번호식 인용 `[n]`과 참고문헌 목록의 불일치

결과는 "살펴볼 것"이지 판정이 아니다. 걸린 항목을 하나씩 보고, 괜찮은 것은 넘긴다. `--text`로 전체
문구를 뽑아 `storyline.md`와 대조하거나 교정에 쓴다.

## 3. 논리 점검

`storyline.md`와 `work/logic_check.md`의 대응표를 덱과 대조한다.

- **제목만 이어 읽기**: 제목(또는 헤드 메시지)만 읽어도 핵심 주장이 전달되는가. 건너뛴 고리가 없는가.
- **논리 사슬 표**(제안서: 문제 → 목표 → 내용 → 성과 / 보고서: 목표 → 수행 → 결과 → 달성도)
  - 모든 세부 목표에 대응하는 내용(결과)이 덱에 있는가
  - 어느 목표에도 속하지 않는 내용(결과)이 끼어 있지 않은가
  - 목표·내용의 이름이 목표 장, 내용 장, 일정표, 달성도 표에서 **글자 그대로** 같은가
- **평가 항목 대응표**: 모든 평가 항목에 다루는 슬라이드가 있는가. 배점이 큰 항목이 충분히 다뤄졌는가.
- **보고서**: 목표·지표 문구가 제안서(협약서)와 같은가. 계획과 달라진 점이 밝혀져 있는가.
- **요약 장**: 본문의 결론과 같은 말을 하는가. 본문에 없는 내용이 요약에만 있지 않은가.
- **결론·기대 효과**: 본문의 결과·목표에서 나오는 것인가.

## 4. 근거 점검

- **수치 일치**: 같은 숫자가 요약, 본문, 표, 그래프에서 같은가. 합계와 비율이 맞는가.
- **원 자료 대조**: 덱의 수치·그래프 값을 사용자가 준 자료에서 찾아 대조한다. 대조하지 못한 수치는
  목록으로 보고한다.
- **단위·기준**: 모든 수치에 단위가 있는가. 기준 시점, 표본 수가 필요한 곳에 있는가.
- **인용**: 인용이 필요한 주장(통계, 선행 연구 결과)에 출처가 있는가. 참고문헌 목록의 서지 정보가
  사용자가 준 것과 같은가.
- **해석의 세기**: 자료보다 강한 표현(입증, 최초, 유일, 세계 최고)이 근거 없이 쓰이지 않았는가.
- **지어낸 것이 없는가**: 내가 채운 문장 중 자료에서 근거를 찾을 수 없는 것이 있으면 지우거나
  `[확인 필요]`로 바꾼다.

## 5. 표기 점검

- 용어·약어가 문서 전체에서 같은가. 약어가 처음 나올 때 풀려 있는가.
- 과제명, 기관명, 연구책임자, 연구 기간, 날짜가 표지·머리글·본문에서 같은가.
- 문체가 한 가지인가(개조식과 서술식이 섞이지 않았는가).
- 그림·표 번호와 본문의 참조가 맞는가. 쪽 번호가 이어지는가.
- 작성 요령(분량, 글자 크기, 파일 형식·이름)을 지켰는가.
- 외부 제출 문서에 미공개 정보나 개인 식별 정보가 들어가지 않았는가.
- 한국어 맞춤법·띄어쓰기를 마지막에 한 번 훑는다.

## 6. 보고

보고 전에 SKILL.md의 "완료 기준"을 하나씩 대조하고 `progress.py show work/progress.json`으로 끝나지 않은
장을 확인한다. 기준을 다 채우지 못했으면 "완성"이라고 하지 않고, 어느 단계의 몇 번 장이 왜 남았는지를
"확인이 필요한 것" 맨 위에 쓴다.

쉬운 말로, 아래 세 묶음으로 보고한다.

```markdown
## 결과
- 파일: <경로> (<장수>)
- 백업: <경로>

## 확인이 필요한 것
1. 슬라이드 7: 예비 실험 그래프의 원 데이터가 없어 받은 그림을 그대로 넣었습니다. 해상도가 낮습니다.
2. 슬라이드 12: 3차년도 정량 목표치가 자료에 없어 [확인 필요]로 두었습니다.

## 제가 임의로 정한 것 (원치 않으시면 되돌립니다)
1. 슬라이드 9와 10의 순서를 바꿨습니다. 방법 설명이 결과보다 먼저 오도록 했습니다.
```

- 검사를 못 한 항목은 못 했다고 쓴다. 대조하지 못한 수치를 "확인함"이라고 쓰지 않는다.
- 질문은 답을 받으면 바로 반영할 수 있는 형태로 쓴다(선택지와 권하는 쪽).
- 사용자가 줘야 하는 자료는 한 목록으로 요청한다.
- 마감이 가까우면 "제출 전에 꼭 고쳐야 하는 것"과 "시간이 되면 고칠 것"을 나눈다.
