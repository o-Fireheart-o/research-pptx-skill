# 템플릿 분석과 템플릿 프로필

템플릿 프로필은 "이 양식으로 슬라이드를 만들려면 무엇을 어디에 어떻게 놓는가"를 적은 문서다. 한 번
써 두면 조립, 검수, 다음 작업이 모두 같은 기준을 쓴다.

## 양식의 종류

| 받은 것 | 읽어 낼 것 |
|---|---|
| 기관 지정 양식(공고문 별지, 발표 자료 양식) | 정해진 목차와 제목, 분량 제한, 필수 항목. **바꾸면 안 되는 것**이 무엇인지 |
| 연구실·기관 템플릿(빈 양식) | 레이아웃, 색, 글꼴, 로고와 쪽 번호 위치 |
| 지난 문서(선배·지난해 제안서, 지난 보고서) | 위의 것 + 구성, 문체, 그림·표를 다루는 방식 |

양식과 함께 작성 요령(글자 크기 하한, 분량, 파일 형식)이 있으면 프로필에 옮겨 적는다. 지키지 않으면
접수 단계에서 불이익을 받을 수 있는 규정이다.

## 분석 순서

1. **구조 읽기**
   ```
   python -I <skill>/scripts/deck_profile.py "<template.pptx>"
   ```
   슬라이드 크기, 레이아웃별 자리 표시자와 사용 횟수, 슬라이드별 레이아웃·첫 문구가 나온다.
   사용 횟수가 0인 레이아웃은 양식을 만든 사람이 쓰지 않은 것이므로 새 덱에서도 쓰지 않는다.
   `.potx`는 `.pptx`로 복사해서 연다.
2. **실제 모습 보기**: 전 슬라이드를 그림으로 뽑아 직접 본다.
   ```
   powershell -ExecutionPolicy Bypass -File <skill>/scripts/ppt_export.ps1 "<template.pptx>" "<out_dir>"       (Windows + PowerPoint)
   soffice --headless --convert-to pdf "<template.pptx>"                          (그 밖의 환경)
   ```
3. **유형 나누기**: 슬라이드를 역할로 묶는다(표지, 목차, 장 구분, 본문-글, 본문-그림, 본문-표, 일정표,
   마무리 등). 같은 레이아웃이 여러 역할에 쓰이기도 하므로 레이아웃 이름이 아니라 역할로 묶는다.
4. **본보기 슬라이드 재기**
   ```
   python -I <skill>/scripts/deck_profile.py "<template.pptx>" 1,3,5,12
   ```
   도형별 위치·크기(inch), 색, 글꼴·크기가 나온다. 이 숫자를 프로필에 옮긴다.
5. **관례 찾기**: 본문 여러 장을 비교해 반복되는 관례를 찾는다.
   - 제목이 주제형("3. 연구 목표")인가 결론형("오차를 30% 줄임")인가. 제목 아래 요약 한 줄(헤드
     메시지)이 있는가
   - 번호 체계(장 `1.` / 절 `1.1` / 항목 `□ ○ -` 등 글머리 기호의 단계)
   - 그림·표 캡션의 위치와 표기("그림 1." / "Fig. 1" / "<표 1>"), 출처 표기 위치
   - 강조 방식(굵게, 색, 밑줄)과 그 색 값
   - 문체(개조식 "~함/~임", 서술식 "~다/~습니다"), 문장 길이, 한 장의 글 분량
   - 쪽 번호, 과제명·기관명 머리글, 로고
   - 화면 위쪽의 진행 표시(다섯 부를 늘어놓고 현재 부를 강조), 번호 배지와 소제목 띠 같은 반복 장식
   - 표의 서식(머리글 색, 출처 열), 결론 줄의 표기(`→ …`, `➢ …`, "~ 완료"), 약어 풀이의 위치
6. **지난 문서의 구성 읽기**: 장 순서와 장마다 슬라이드 수를 적는다. 스토리라인의 출발점이다.

## 프로필 양식

`work/template_profile.md`로 저장한다. 아래 값은 양식을 보여 주는 예시이고, 실제 템플릿에서 잰 값으로
채운다.

```markdown
# 템플릿 프로필: <템플릿 파일명>

## 기본
- 슬라이드 크기: 13.33 × 7.50 in (16:9)
- 글꼴: 제목 <…>, 본문 <…>
- 색: 주색 <hex>, 강조 <hex>, 보조 <hex>
- 전체 순서: 표지 → 목차 → 장마다 [장 구분 → 본문 …] → 참고문헌 → 마무리

## 지켜야 하는 규정 (작성 요령)
- 목차: 공고문 별지 2의 6개 항목 순서·제목 고정
- 분량: 본문 20장 이내 / 발표 15분
- 글자 크기: 본문 12pt 이상

## 슬라이드 유형
| 유형 | 레이아웃 이름 | 본보기 슬라이드 | 들어가는 것 |
|---|---|---|---|
| 표지 | <…> | 1 | 과제명, 기관·연구책임자, 날짜 |
| 장 구분 | <…> | 3 | 장 번호와 제목 |
| 본문-글 | <…> | 5 | 제목, 헤드 메시지 1줄, 본문 3단계 글머리 |
| 본문-그림 | <…> | 8 | 제목, 그림 1~2개, 캡션, 출처 |
| 본문-표 | <…> | 12 | 제목, 표, 캡션 |

## 유형별 배치 (inch)
### 본문-그림
- 제목: 자리 표시자 0, x0.60 y0.30
- 헤드 메시지: x0.60 y1.05, 16pt 굵게, 주색
- 그림 영역: x0.60 y1.70 w12.10 h4.60
- 캡션: 그림 아래 가운데, 11pt, "그림 N. 제목"
- 출처: 왼쪽 아래 x0.60 y6.95, 9pt 회색

## 관례
- 제목: 주제형, 헤드 메시지에 결론
- 글머리: □ → ○ → - (3단계)
- 문체: 개조식(명사 종결, "~함")
- 인용: 번호식 [1], 참고문헌은 마지막 장

## 쓰지 않는 것
- 사용 횟수 0인 레이아웃: <목록>
- 템플릿에 없는 색·글꼴·장식

## 템플릿에 본보기가 없는 유형
- <예: 추진 일정표 → 본문-표 유형에 도형으로 그림. 막대 색은 주색>
```

## 양식 보관함

기관이 그때그때 달라도 같은 기관·같은 사업에는 다시 내게 된다. 한 번 분석한 양식은 보관해 두고 다시
쓴다. 분석을 되풀이하지 않아 시간과 사용량이 줄고, 지난번에 승인받은 모습을 그대로 이어 갈 수 있다.

위치는 스킬 폴더 밖, 사용자 홈의 `~/.research-pptx/profiles/`다(스킬을 새로 설치해도 지워지지 않는다).

```
~/.research-pptx/profiles/
  index.md                          한 줄에 하나: 폴더 이름 | 기관·사업 | 문서 종류 | 저장한 날 | 양식 파일 이름
  <기관>_<사업>_<종류>/              예: A재단_기초연구_제안발표
    template_profile.md             템플릿 프로필 (+ 샘플에서 승인된 값, 작성 요령)
    template.pptx                   양식 원본 사본
```

**찾기(1단계 시작할 때).** `index.md`를 읽어 같은 기관·사업·종류가 있는지 본다. 있으면:
1. 그 프로필을 `work/template_profile.md`로 복사한다.
2. 이번에 받은 양식이 보관된 것과 같은지 `deck_profile.py`의 첫 화면(크기, 레이아웃 목록)만 비교한다.
   같으면 분석을 건너뛴다. 레이아웃이 달라졌으면 달라진 부분만 다시 재고 프로필을 고친다.
3. 사용자에게 "지난번 <기관> 양식 기록을 씁니다"라고 한 줄로 알린다.

**저장(문서를 마쳤을 때).** 새 양식이었거나 프로필을 고쳤으면 저장하겠냐고 한 번 묻고, 좋다고 하면
폴더를 만들고 `index.md`에 한 줄을 더한다. 프로필 끝에 아래를 붙인다.

```markdown
## 샘플에서 승인된 것 (<날짜>, <문서 이름>)
- 본문 14pt, 한 장 400자 안팎
- 결론 줄: 아래쪽 `→` 굵게
- 표: 머리글 <hex>, 출처 열 있음

## 이 양식에서 겪은 것
- <예: 위쪽 진행 표시는 레이아웃이 아니라 슬라이드마다 그려야 함>
```

- 보관하는 것은 **양식과 그 규칙**이다. 연구 내용, 완성본, 데이터는 보관함에 넣지 않는다.
- 사용자가 준 양식 파일에 지난 과제의 내용이 들어 있으면(지난 발표 자료를 양식으로 쓴 경우) 사본을
  저장하기 전에 넣어도 되는지 묻는다.
- 같은 이름의 기록이 이미 있으면 덮어쓰지 말고 무엇이 달라졌는지 말한 뒤 갱신할지 묻는다.

## 사용자에게 보고할 내용

프로필 전체를 붙이지 말고 쉬운 말로 요약한다.

- 슬라이드 유형 몇 가지와 각각의 쓰임
- 지켜야 하는 규정(정해진 목차, 분량, 글자 크기)
- 눈에 띄는 관례 서너 가지
- 양식에 없어서 정해야 하는 것(예: 일정표의 본보기가 없음, 제목을 결론형으로 써도 되는지)
