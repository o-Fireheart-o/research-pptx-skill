# 스토리라인: 뼈대 덱과 storyline.md

스토리라인은 두 가지 모습으로 존재하고, 내용은 같다.

| | 뼈대 덱 `storyboard.pptx` | 글 파일 `storyline.md` |
|---|---|---|
| 누가 보나 | **사용자.** PowerPoint에서 보고 고친다 | 만드는 쪽(AI). 구조를 읽고 기록한다 |
| 모습 | 1번 장은 한 장 흐름도, 그 뒤로 실제 슬라이드 한 장마다 기획 장 하나 | `###` 한 덩어리가 슬라이드 한 장 |
| 고치는 법 | 슬라이드를 끌어 순서를 바꾸고, 제목과 내용을 고쳐 쓴다 | 메모장에서 줄을 고친다 |

사람은 슬라이드로 된 흐름을 볼 때 가장 빨리 이해하고, 순서를 끌어서 바꾸는 것이 가장 쉽다. 그래서
사용자에게는 **뼈대 덱을 기본으로** 내놓는다. `storyline.md`는 뼈대 덱을 읽을 때마다 갱신되는 기록이고,
조립과 검수는 이 파일을 기준으로 한다. 글로 쓰는 편이 편한 사용자는 `storyline.md`를 직접 고쳐도 된다.
어느 쪽을 고쳤든 다른 쪽을 바로 맞춘다. **두 파일이 어긋난 채로 다음 단계로 가지 않는다.**

## 뼈대 덱

```
python -I <skill>/scripts/storyboard.py make storyline.md storyboard.pptx --template "template/<양식>.pptx"
python -I <skill>/scripts/storyboard.py read storyboard.pptx storyline.md
python -I <skill>/scripts/storyboard.py map  storyboard.pptx
```

- `make`: `storyline.md`에서 뼈대 덱을 만든다. `--template`을 주면 그 양식의 크기·테마·레이아웃을 써서
  완성본과 비슷한 모습이 된다(레이아웃은 `--layout "<이름>"`으로 고를 수 있고, 기본은 양식에서 가장
  많이 쓰인 것). 양식의 장식과 글 상자가 겹치면 다른 레이아웃을 고르거나 `--template` 없이 흰 바탕으로
  만든다. 만든 뒤 렌더링해서 겹침이 없는지 본다.
- `read`: 사용자가 고친 뼈대 덱을 읽어 `storyline.md`를 갱신한다. 이전 파일은 `.bak`으로 남고, 제목이
  바뀌거나 생기거나 없어진 장과 순서 변경을 알려 준다.
- `map`: 1번 장의 흐름도를 지금 슬라이드 순서대로 다시 그린다. `read` 뒤에 항상 돌린다.

### 뼈대 덱의 한 장

| 자리 | 뜻 | `storyline.md`에서 |
|---|---|---|
| 제목 | 그 장의 결론 한 문장 | `### …` |
| 본문 | 담을 내용. `•`는 항목, 들여쓴 `–`는 하위 항목 | `- …` |
| 빨간 `? …` 줄 | 아직 못 정한 것 | `? …` |
| 점선 상자 | 넣을 그림·표(`그림: 설명`, 아래 줄에 파일) | `그림:` `표:` |
| 회색 `출처: …` 줄 | 수치·주장의 출처 | `출처:` |
| 오른쪽 위 작은 글씨 | 장(章) 이름 | `## …` |
| 슬라이드 노트 | 만드는 쪽에 전할 말 | `메모:` |

1번 장(흐름도)에는 장마다 기둥이 하나씩 있고 그 아래 슬라이드 제목 상자가 순서대로 놓인다. 빨간 테두리는
`?`가 남은 장, 회색 머리는 아직 슬라이드가 없는 장이다. 흐름도 위의 `종류:`, `발표:`, `핵심 주장:` 줄과
문서 제목은 고치면 읽힌다. **흐름도의 상자는 보기 전용**이라 거기서 옮기거나 고친 것은 읽히지 않는다.

### 사용자에게 안내할 것 (쉬운 말로)

- 순서 바꾸기: 보기 > 여러 슬라이드에서 끌어 옮긴다.
- 장 추가: 비슷한 장을 복제해서 제목과 내용을 고쳐 쓴다. 빈 슬라이드를 새로 만들어도 된다(맨 위 글이
  제목으로 읽힌다).
- 장 삭제: 슬라이드를 지운다.
- 다른 장(章)으로 옮겼으면 오른쪽 위 장 이름도 고친다. 잊어도 된다. `read`가 "장 '…'의 슬라이드가
  떨어져 있음"으로 알려 주므로, 그때 어느 장에 넣을지 사용자에게 묻는다.
- 그림을 미리 붙여 넣어도 된다. 어느 장에 그림이 들어 있는지 기록된다.
- 고친 뒤에는 **저장하고 PowerPoint를 닫은 다음** 알려 달라고 한다(열려 있으면 흐름도를 다시 그려
  저장할 수 없다).

### 읽을 때 주의

- 사용자가 만든 슬라이드는 약속한 자리 이름이 없다. 맨 위 글 상자를 제목으로, 나머지를 내용으로 읽는다.
  읽은 결과가 이상하면(제목과 내용이 뒤바뀜 등) 추측으로 넘기지 말고 그 장을 렌더링해 보고 확인한다.
- 상자와 화살표로 그린 그림은 글만 읽힌다. 연결 관계가 중요해 보이면 렌더링해서 눈으로 보고, 읽은
  내용을 사용자에게 되물어 확인한다.
- 사용자가 뼈대 덱을 고친 뒤에는 `make`를 다시 돌리지 않는다(사용자가 손본 배치가 지워진다). 고칠 것이
  있으면 해당 장만 고친다. `make`는 처음 만들 때와 `storyline.md`를 크게 다시 썼을 때만 쓴다.

## storyline.md 양식

`storyline.md`는 뼈대 덱과 같은 내용을 글로 적은 것이다. 한 덩어리가 슬라이드 한 장이고, 줄 머리의
기호와 낱말로 무엇이 본문이고 무엇이 요청인지 구분된다.

```
# 문서 제목(과제명)

종류: 제안서 발표
발표: 15분 + 질의 10분
독자: 같은 분야 심사위원
핵심 주장: 이 문서가 말하려는 것 한 문장
평가: source/공고문.pdf 12쪽
양식: template/발표양식.pptx

## Ⅰ. 필요성

### 이 장에서 말하려는 결론 한 문장
- 결론을 받치는 내용
  - 하위 내용(두 칸 들여쓰기)
그림: 넣고 싶은 그림 설명 (figures/파일.png)
표: 넣고 싶은 표 설명 (source/파일.xlsx)
출처: 숫자나 주장의 출처
메모: 만드는 쪽에 전할 말. 슬라이드에는 들어가지 않는다
시간: 1.5
? 아직 정하지 못한 것, 확인할 것
```

| 표시 | 뜻 | 꼭 필요한가 |
|---|---|---|
| `# ` | 문서 제목 | 한 번 |
| `키: 값` (첫 장 앞) | 문서 설정. `종류`, `발표`, `독자`, `핵심 주장`, `평가`, `양식` | `핵심 주장`은 꼭 |
| `## ` | 장(章) | 양식의 목차대로 |
| `### ` | **슬라이드 한 장.** 그 장의 결론을 한 문장으로 | 이것만 있어도 된다 |
| `- ` | 슬라이드에 담을 내용. 들여쓰면 하위 항목 | 선택 |
| `그림:` `표:` | 넣을 그림·표. 파일이 있으면 끝에 괄호로 경로 | 선택 |
| `출처:` | 수치·주장의 출처 | 수치가 있으면 |
| `메모:` | 만드는 쪽에 전하는 말(배치, 강조, 주의) | 선택 |
| `시간:` | 그 장의 발표 시간(분) | 선택 |
| `? ` | 미정·확인 필요. 어디에나 쓸 수 있다 | 선택 |
| `<!-- … -->` | 무시되는 주석 | — |

표에 없는 줄(그냥 쓴 문장)은 그 슬라이드의 본문으로 본다. 양식을 조금 틀려도 읽을 수 있게 되어 있으니
사용자가 틀리게 썼다고 고쳐 쓰라고 하지 않는다. 정리해서 돌려준다. 빈 양식과 예시는
`assets/storyline_template.md`에 있다.

## 세 가지 시작점

사용자가 가진 것에 따라 시작이 다르다. 어느 경우든 `storyline.md`를 만들고 뼈대 덱으로 보여 준다.

1. **자료만 있다**(공고문, 초안 문서, 지난 발표, 논문, 데이터)
   자료를 읽고 `storyline.md` 초안을 쓴다. 자료에서 찾지 못한 내용은 지어내지 않고 `?`로 남긴다.
2. **머릿속에 흐름이 있다**
   사용자가 말로 불러 주거나, 제목만 적은 슬라이드 몇 장(또는 `###` 줄 몇 개)을 준다. 받아서 자료로
   내용·그림·출처를 채운다.
3. **이미 만든 것이 있다**(한글·워드 개요, 손으로 그린 흐름, 지난 덱, 사용자가 직접 만든 뼈대 PPT)
   그대로 읽어 옮긴다. 옮기면서 순서나 표현을 바꾸지 않고, 바꾸자고 제안할 것은 `?`로 따로 적는다.

## 주고받는 순서

1. `storyline.md` 초안을 만든다(위 세 경우 중 하나).
2. `python -I <skill>/scripts/storyline_check.py storyline.md`로 장별 분량, 발표 시간 대비 장수, 비어
   있는 장, 파일 없는 그림·표, `?` 목록을 확인한다.
3. `storyboard.py make`로 뼈대 덱을 만들고 렌더링해 겹침이 없는지 본 뒤 사용자에게 준다. 함께 말할 것:
   1번 장 흐름도부터 보라는 것, 제목만 이어 읽어 이야기가 이어지는지 봐 달라는 것, 정할 것 서너 개.
4. 사용자가 PowerPoint에서 고치거나 말로 고칠 곳을 알려 준다("3번과 4번 바꿔 줘", "역량은 한 장으로").
5. 덱을 고쳤으면 `storyboard.py read` → `storyline_check.py` → `storyboard.py map`. 말로 받았으면
   `storyline.md`와 뼈대 덱의 해당 장을 함께 고치고 `map`.
6. 바뀐 점을 짧게 되짚어 확인받는다("5번을 2번 뒤로 옮기셨고, 역량 장이 한 장이 됐습니다").
7. `?`가 남아 있어도 확정할 수 있다. 다만 남은 `?`는 완성본에 `[확인 필요]`로 들어간다는 것을 알린다.
8. 확정되면 `storyline_check.py storyline.md --json work/storyline.json`으로 조립용 데이터를 만든다.
   뼈대 덱은 기획 기록으로 남겨 두고, 완성본은 `output/`에 따로 만든다.

## 결론 문장 쓰는 요령 (사용자에게 안내할 때)

- 제목은 "~에 대하여"가 아니라 "~이 ~하다"로 쓴다. "실험 결과" 대신 "제안 소재가 저농도 오차를
  절반으로 줄였다". 기관 양식의 슬라이드 제목이 주제형이어도 여기에는 결론을 쓴다. 양식에 맞춰 제목과
  요약 줄로 나눠 넣는 일은 만드는 쪽이 한다.
- 한 장에 결론이 둘이면 두 장으로 나눈다.
- 내용은 완성 문장이 아니어도 된다. 낱말, 숫자, "지난 보고서 5쪽 그림"처럼 써도 된다.
- 모르는 것은 비워 두지 말고 `?`로 쓴다. 비워 두면 빠뜨린 것인지 필요 없는 것인지 알 수 없다.
- 그림은 있는 파일이면 경로를, 없으면 어떤 그림이 필요한지 말로 쓴다.

## 만드는 쪽이 지킬 것

- 사용자가 쓴 결론 문장의 뜻을 바꾸지 않는다. 다듬더라도 주장의 세기와 범위는 그대로 둔다.
- 사용자가 쓰지 않은 수치·결과·문헌을 채워 넣지 않는다. 자료에서 가져온 내용에는 `출처:`에 어느
  자료의 어디인지 적는다.
- 덧붙인 장이나 내용은 `메모: (제안) …`으로 표시해 사용자가 쓴 것과 구분한다.
- 완성본을 만든 뒤 구성이 바뀌면 `storyline.md`를 먼저 고친다. 사용자가 완성본에서 직접 구성을 바꿨으면
  그 덱을 읽어 `storyline.md`를 맞춘다.
- 대응표(논리 사슬, 평가 항목)는 `storyline.md`에서 만들어 `work/logic_check.md`에 둔다. 사용자가 관리할
  파일을 늘리지 않는다.
